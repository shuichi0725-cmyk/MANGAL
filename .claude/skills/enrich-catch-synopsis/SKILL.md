# キャッチ/詳細エンリッチ (= トリガー「エンリッチして」「キャッチ詳細作って」)

**キャッチ=検索・一覧に出る惹句 / 詳細(synopsis)=作品ページのあらすじ**。
両者が似た文になる事故が再発してきた(2026-07-06 ユーザ指摘)ため、役割定義と生成規律をここに固定する。
あわせて同じ材料からジャンル・要素タグも付与する(この一連は過去に何度も実施→この skill が正本)。

## ★何をどこまで付けるか (= 2026-07-14 ユーザ裁定・エンリッチの定義)

| 対象 | 付与するもの |
|---|---|
| **2巻以上**+材料(楽天caption)あり | キャッチ+詳細+ジャンル(フル) |
| **1巻のみ**+材料あり | **ジャンルのみ**(キャッチ/詳細は書かない) |
| 材料なし(楽天にcaption無し/商品無し) | Gemini同定でジャンルのみ(任意・下記)/それも不可なら**空のまま**(捏造しない)+欠落表 |

- 「楽天でジャンルとれる」の実体 = 楽天が直接くれるのではなく、**captionを材料にAIがmaster32から選んで
  `genres_provisional: true`を立てる**(楽天から直接来るのは分野系サブジャンルだけ)。
- ★**Gemini同定**(2026-07-13 実証・genre:other撲滅で407作適用): 楽天に材料が無い古い作品は
  `python scripts/_gemini-genre-probe.py`(gemini-3.1-flash-lite・15RPM・429即中断・再開可)で
  題+著者+年から同定。採用ゲート=**known=true × confidence high/medium × master32検証**の3段。
  art_book/non_manga判定はFLAG(掲載境界)へ、unknown/lowは据置。無料枠~500req/日(PT深夜リセット)。

## Step1: 材料収集(全巻の紹介文を読む)
```
python scripts/_enrich-captions.py --missing --src .preview-data/manga --live   # 欠け頁を自動抽出
python scripts/_enrich-captions.py --slugs a,b,c --live                          # 指定頁
```
- 楽天itemCaptionを**予約キャッシュ→liveの順で全巻分**集める(1.2s/req・429即中断)。
- ★1巻だけでなく**在る巻ぜんぶ読む**(2026-07-06 ユーザ裁定)。ただし書く内容の縛りは下記。
- 出力 `.cache/enrich/materials.jsonl`(AI生成バッチの入力)。

## Step2: AI生成の規律 (= キャッチと詳細を書き分ける・最重要)
材料(全巻captions)を読んだ上で:

| | キャッチ | 詳細(synopsis) |
|---|---|---|
| 役割 | 一覧で足を止めさせる**フック** | 作品の**設定と物語**の説明 |
| 長さ | **20〜40字** | **60〜120字** |
| 視点 | 感情・魅力・引き(「〜する物語」等の説明調を避ける) | 主人公・世界設定・物語の起点(1〜2巻の範囲) |
| 語り | 体言止め/呼びかけ可・煽りすぎ禁止 | 平叙文・客観 |
| 禁止 | 詳細の短縮コピー(**同じ文の長短2種は不可**) | 最新巻の展開・結末(ネタバレ) |

- ★**丸写し禁止**(verbatim撲滅): captionは材料であり、要約・言い換えで書く。
- ★後半巻のcaptionは「作品のトーン・ジャンル理解」にだけ使い、**文面には1〜2巻の範囲しか書かない**。
- 楽天にも材料が無い作品(実測: 欠けの~27%)は**空のまま**(捏造しない)+欠落表報告。

## Step3: ジャンル・要素の付与(同じ材料から)
- **master 32キーから選ぶだけ**(data/genres.yml が正本。新語創作・英語混入禁止 [[ai_genre_closed_vocabulary]])。
- 1〜4個。該当なしは空(otherに落とさない)。**genres_provisional: true を必ず立てる**(AI由来マーク)。
- demographic は楽天サブジャンル写像(少年/少女/青年/レディース)が既にあれば触らない。

## Step4: 適用
- **previewドラフト頁(予約②③④等)**: yml へ直接書く(ドラフト自体がソース)。
- **本番既存頁**: 適用スクリプトで manga.v2 へ純粋追加(空欄のみ埋める)+ 変更slugを「反映して」。
  永続化seed=`catch-ja.json`(既存)+`synopsis-slug-ja.json`(2026-07-06新設・promote結線済=空欄fill)。上書き禁止・純粋追加のみ。
- 100件/batchで処理し、`applied=N, missing=0, overwrites=0` を毎バッチ確認(月次蒸留の保護策と同じ)。

## 過去の実績・教訓(re-inventしない)
- 2026新刊蒸留: 3段fill+AI enrich(verbatim撲滅・最終巻丸写し禁止はここ由来)。
- 楽天あらすじ→ジャンル: 教師あり+較正+2パス救済で6,638作付与([[genre_from_rakuten_story_plan]])。
- 実測(2026-07-06): キャッチ/詳細欠けの~73%は楽天に材料あり(1巻紹介文はサンプル8/10)=「楽天に無いから空」とは限らない、必ずStep1で突合する。
