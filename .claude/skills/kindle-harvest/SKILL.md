# Kindle収穫 (= 2026-11-23 新設。電子優先)

**トリガー語**
| 言い方 | やること |
|---|---|
| 「Kindle収穫して」「Kindle収穫続けて」 | 手順1→2(続きから回す。どちらも同じ) |
| 「Kindle収穫止めて」 | 手順3 |
| 「Kindle収穫どう?」 | 手順1だけ打って数字を報告 |

目的: 頁の各巻に Kindle 版の ASIN を付け、Kindle リンクを `/dp/<ASIN>`(ブラウザで開く)にする
([[kindle_link_browser_not_app]])。★**集めるだけ**。`data/seeds/kindle-asin.jsonl` への適用・反映は**ユーザGO後に Opus が行う**。

## ★絶対に守ること (= 一番まずいのは「叩きすぎて API が使えなくなる」こと)

1. **間隔を変えない**。既定 = 1回12秒・**24時間の回数上限なし**・**200以外1回で即停止**(2026-11-25 ユーザ指定を道具の既定に焼いた。旧既定は直近24時間2,700回で自分で休む仕組みで、総数だけ見て何時間も始まらなかった=ユーザ「総計をみて開始しないので修正して」)。環境変数を付けずに起動すればこの条件になる。429/403 の見出し・本文は `.cache/kindle-asin/throttle-429.jsonl`
   - `KINDLE_ASIN_FAST=1` を**付けない**(1秒間隔=すぐ429)。`PACE_PER_UNIT`/`KINDLE_ASIN_PACE`/`KINDLE_ASIN_BUDGET` を変えない。
2. **二重起動しない**。走っている間にもう1本起動すると叩く速さが倍になる。道具は台帳(`.cache/kindle-asin/calls.log`)に5分以内の呼出があると起動を拒む。拒まれたら**それが正しい**=起動し直さない。
3. **429 / 403 が出たら道具が自分で止まる。再起動しない**。ユーザに報告して待つ。
   - 429 = 叩きすぎ(枠切れ)。**最低1時間休ませてから**ユーザの指示で再開。
   - 403 `AssociateNotEligible` = アソシエイトの売上条件を失った = API そのものが使えない。即報告。
4. **鍵を表示しない**。`.env` の `AMAZON_CREATORS_*` を cat / echo / ログ出力しない。repo は公開。
5. **道具を直さない**(Sonnet 運転時)。照合の誤り・例外を見つけたら報告に書くだけ。直すのは Opus。

## 手順

```
# 1. 現在地(★まずこれ。走っている/止まっている・済/残・採る/見直し/なし)
python scripts/_kindle-asin-harvest.py status

# 2. 続きを回す(background・ログはファイルへ追記)
python scripts/_kindle-asin-harvest.py harvest --kindle-only >> .cache/kindle-asin/harvest/run-$(date +%Y%m%d%H%M).log 2>&1
#   → Bash の run_in_background で起動。終わると通知が来る(ポーリングしない)。
#   → 50頁ごとに1行進み具合が出る。確かめたい時は ログの末尾2行だけ読む(全部読まない)。

# 3. 止める(次の頁の前で止まる。プロセスを kill しない=書きかけを残さない)
touch .cache/kindle-asin/harvest/STOP
```
- `--kindle-only` を**必ず付ける**(付けないと紙の商品頁の照会もする=単位の約7割を食い、遅くなる)。
- 順番は決まった種で混ぜた順(人気順ではない)。`done.txt` に済んだ頁を書くので、止めても次は続きから。
- 速さの目安: 12秒/回 = 1日 最大約7,200回。実際の枠(TPD)は売上で上下し、超えると429で止まる(11/25 観察=直近24時間5,193回でも429が出た)。

## 出力 (= すべて `.cache/kindle-asin/harvest/`、git 外)

| ファイル | 中身 |
|---|---|
| `candidates.jsonl` | 巻ごとの判定。`verdict` = take(採る) / review(見直し) / none(Kindle版なし) |
| `done.txt` | 済んだ頁(SRC slug) |
| `run-*.log` | 実行ログ |
| `../raw/YYYYMM.jsonl.gz` | API の生応答(取り直さないための控え) |

判定(ユーザ裁定「そろってれば取る」): A=題+巻番号+発売日±62日 → 採る / B=日付ズレ → その版の巻が Kindle 側で全部そろっている時だけ採る / 他は見直し。

## 報告の形 (= 日本語・短く)

- 1行目: 走っている/止まった(理由: 自然終了 / STOP / 429 / 403)
- `status` の数字をそのまま引用(済/残・採る/見直し/なし・直近24時間の単位)
- 止まった理由が 429/403 なら「再開はユーザの指示待ち」と書く

## 後回し (= この skill ではやらない)

- 紙の商品頁の照会(`--kindle-only` を外すと再開。または版名つきの本売り場検索=うる星で 71冊→約26単位の実測あり)
- 見直し(review)の裁定・seed への適用・テスト反映 = Opus + ユーザGO
