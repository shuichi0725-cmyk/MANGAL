# 依頼書: 自分だけの本棚(マイ本棚)

2026-09-28 ユーザと相談して確定。 クラウドセッション向け。

## 1行目 = 画面が何に変わるか

**作品頁に「しまう」ボタンが付き、押した漫画が `/shelf` の「もってる/気になる/ほしい」3段の本棚に並ぶ。
「もってる」の棚は、1巻から何巻まで持っているかを覚えていて、「10巻まで所持 → 11・12巻が出ています」を札ごとに出す。**

既存頁に新しいフィルターを足すものではない。 本棚は独立した1画面。

## 決まっていること(ユーザ裁定・変えない)

1. **単位は作品**。 ただし「もってる」だけは **1巻から連続で持っている最後の巻** を数字1つで持つ。
   - 1〜10巻所持 → `10` / 1〜6, 8, 9巻所持(7巻欠け)→ `6`。 8・9巻は記録しない(割り切り)。
2. **棚は3つ固定**: `もってる` / `気になる` / `ほしい`。 1作品は同時に1つの棚だけ(移動はできる)。
   - もってる = 巻数あり・新刊/続きの巻を知らせる
   - ほしい = 巻数なし・買い物リスト
   - 気になる = 巻数なし・読むか迷っている
   - ユーザが棚を増やす機能は今回は作らない。
3. **保存先 = ① 端末(ブラウザ)に保存 + ② 棚のURL**。 ログイン・サーバ保存は作らない(サイトは個人情報ゼロ方針)。
   - ① IndexedDB か localStorage。 読み書きは必ず try/catch(保存不可環境=黙って空の棚)。
   - ② 棚の中身を URL(または貼り付け用の文字列)に書き出し、別端末で開くと取り込める。 用途=機種変更・Safari の7日消去の保険・人に棚を見せる。
     取り込みは「上書き/合流」を選ばせる。 見せる用途では「見るだけ(自分の棚に入れない)」表示も可。

## 保存する中身(1作品あたり)

`slug` / `title` / `cover`(保存時点の書影URL) / `shelf`(3択) / `owned`(もってるの時だけ・整数) / `edition`(任意・版ラベル) / `addedAt` / `updatedAt`

- **slug は変わることがある**(改名・重複頁の統合)。 表示時の解決順:
  1. 索引(`useMangaIndex`)に slug があればそれを使う
  2. 無ければ、その作品だけ `/manga/<旧slug>` を取得し、301 転送先の slug を受け取って保存値を書き換える
     (本番は KV `REDIRECTS` で全件転送。 テスト環境は `public/_redirects` の2,000件だけ=部分的にしか効かない、で良い)
  3. それでも無ければ「この作品は見つからなくなりました」と保存済みの題名+書影で表示。 **自動削除しない**(消すのは本人)
  - 統合で2つが同じ slug になったら1つにまとめる(owned は大きい方)。
- 種2のシリーズ番号(`series.id`)は使わない = シリーズと公開頁は1対1でない(複数シリーズを1頁に統合/1シリーズを複数頁に分割がある)。

## 表示の材料 = 既存の索引の読み込みを使う(★厳守)

- 本棚の書影・題名・巻数・状態は **`lib/useMangaIndex.ts` の `useMangaIndex()`** で引く(先頭100件→列形式の全件→端末保存、の新しい読み込み経路)。
  **見本 JSON を作る・索引を別に作るのは禁止**。 必要なら既存の読み込みに足すのは可。
- 使うフィールド: `total_volumes` / `max_edition_volumes` / `latest_date` / `status` / `cover` / `catch`(withCatch)/ `genres`。
  `total_volumes` の意味(どの版の巻数か)は `scripts/_build-list-index.py` で確かめてから使うこと。
- 「もってる」の札の表示例:
  - `owned < 既刊` → 「10巻まで所持 → 11・12巻が出ています」
  - `owned == 既刊` かつ連載中 → 「最新刊まで揃っています」
  - `owned == 既刊` かつ完結 → 「全巻揃っています」 / 完結で未達 → 「完結済み・あと2冊で全巻」
- 版: 既定は作品頁の先頭の版(ほぼ通常版)。 作品頁から登録する時だけ版を選べる(版ごとの巻数は索引に無く、作品頁のデータにある)。
  版を選んだ作品は「既刊」を登録時点の値で持ち、索引の `total_volumes` とは比べない(注記を出す)。
- 続きの巻の購入導線: 既存の `components/AffiliateLink.tsx` / `lib/amazon.ts` を流用できるなら使う。 無理なら作品頁の巻一覧へのリンクで良い。
  ★**価格を静的に書かない**(サイトの厳守ルール)。

## 作品頁の「しまう」ボタン

- 置き場所: `app/manga/[slug]/page.tsx` の題名まわり(ShareButtons 付近)。 押すと 3棚を選ぶ小さなパネル。
  もってるを選んだら「何巻まで持ってる?」を数字で(既刊を上限に。 既定=既刊)。
- 既にしまってある作品は、どの棚か・何巻までかを表示し、変更/取り出しができる。
- ★サーバ描画では常に「しまう」(未登録)の見た目で出し、保存の読み出しは水和後(useEffect)。 描画中に localStorage を読まない
  (水和ずれ・`scripts/_check-ssr-content.py` の空HTML型を踏まない)。

## ★本番に出さない(テスト環境だけ)

- `/shelf` は **`app/shelf/page.preview.tsx`**(next.config.ts の pageExtensions で、プレビュー用データでビルドした時だけ頁になる)。
- 作品頁のボタンは共通の頁に入るので、ファイル名では隠せない。 **next.config.ts で `isPreviewData` の時だけ
  `NEXT_PUBLIC_PREVIEW_FEATURES=1` を env に流し、ボタンはそれが無ければ `null` を返す**。 本番ビルドには一切出ないこと。
- ヘッダー/ナビ(共通シェル)には触らない。 触る場合は配線ゲート(`.claude-memory/shell_wiring_gates.md`)を回す。 本棚への入口はテスト環境のボタンパネル内のリンクで足りる。

## 見た目

- 本棚らしさは「棚に並ぶ書影」で出す(3段の棚・各段は横スクロール or 折り返しグリッド)。 スマホ幅(360px)基準。
- 棚の札 = 書影+題名+(もってるなら)所持状況の1行。 札に触れると作品頁へ。 長押し/メニューで棚移動・巻数変更・取り出し。
- 空の棚には「作品頁の『しまう』から入れられます」を出す。

## 完了条件

- `npx tsc --noEmit` / 既存テスト green。 保存・読み出し・slug解決(転送)・棚URLの書き出し→取り込み・同一slug統合 の純関数にテストを付ける。
- `MANGAL_DATA_DIR=.preview-data` のビルドで `/shelf` が出て、通常ビルドで `/shelf` もボタンも出ないことを確認。
- push は最後に1回(`claude/manga-database-affiliate-3x0ms`)。 追いpushするとプレビューのビルドが中断される。

## 今回やらないこと

- ログイン/同期、ユーザが棚を増やす、巻ごとの所持管理、通知(プッシュ)、魔法の書架(星図・札めくり)との連携。
  連携は本棚が動いてから(「自分の棚から旅を始める」「棚のどれとも重ならない一冊」)。
