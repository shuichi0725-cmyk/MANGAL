### D-2. ★実証済みの取りこぼし: あらすじ検品は「短すぎるあらすじ」を構造的に見ていない (2026-07-30)

- 発見: エンリッチ(短キャッチrequeue batch-0023)で **`chika-chan-to`(ちかちゃんと!)** の本番あらすじが
  **「あつ森を舞台に島の暮らしを描く、ほのぼのコメディ。」= まるごと別作品**だった。BL作品に『あつまれ どうぶつの森』の説明。
- 原因は **`_synopsis-audit.py` L128 の `if len(syn_t) < 4: continue`**(内容語4語未満=材料不足として判定対象外)。
  当該あらすじの内容語は **「舞台」「コメディ」の2語だけ**なので、交差スコア0.0でも**flagされずに素通り**していた。
- 実測: pagemap 28,652件中 **779件がこの穴に落ちている**(内容語<4)。うち **楽天caption有=339 / 無=440**。
  文字数は20字台が417件と大半で、**短あらすじ再生成キュー(`synopsis-short-requeue.tsv`)と重なる層**。
- 帰結2つ:
  1. **短いあらすじは「短い」だけでなく「誤り」も混じる**。エンリッチで書き直せば副次的に是正されるが、
     caption無しの440件は書き直しも監査もされない**二重の死角**として残る。
  2. 検品柱側の手当て案 = 短い側は交差スコアでなく**別の証拠**(題名トークンとの完全非交差 + 他頁題名との強交差=swap相手推定)で拾う。
     いまの実装は swap相手推定を「flag後」にしか回さないので、**<4語は先に相手推定へ回す**だけで拾える公算が高い。
