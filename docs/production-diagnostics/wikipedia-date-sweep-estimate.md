# Wikipedia発売日 一括掃引の見積り (2026-09-03 実測)

ユーザ裁定「wikiに発売日が載ってる場合は採用でよい」を**全DBへ広げた場合**の規模。
すべて機械計測(推定は重み付けのみ)。生成物 = `.cache/jawiki-manga-titles.json` /
`.cache/jawiki-title-hits.json` / `.cache/wiki-estimate.json`、記事キャッシュ = `.cache/wiki-sample/`。

## 3. ★決定的検証: 突合できた675巻を楽天salesDateで裁定

| 状態 | 巻 | 率 | 扱い |
|---|---|---|---|
| 完全一致(変更不要) | 231 | 34% | — |
| **月ズレ・楽天=wiki支持** | 194 | 29% | ✅ 適用 |
| 月ズレ・楽天=本番支持 | 17 | 3% | ⛔ skip |
| **日ズレ・楽天=本番支持** | **118** | **17%** | ⛔ **skip(本番が正しい)** |
| 日ズレ・楽天=wiki支持 | 40 | 6% | ✅ 適用 |
| 日ズレ・三者バラバラ | 40 | 6% | ⛔ 保留 |
| 日付獲得(本番YYYY-MM→wikiに日)・楽天は月のみ | 32 | 5% | ✅ 適用(楽天は反証にならない) |
| 日付獲得・楽天が別日 | 3 | 0.4% | ⛔ 保留 |

★**月レベルではWikipediaが強い(月ズレ211巻の92%を楽天が支持)**。
★**しかし日レベルでは本番の方が正しいことが多い(日ズレ198巻中118=60%が楽天=本番支持)**。
= **無条件採用は 675巻中118巻(17%)を劣化させる**。楽天との2ソースゲートが必須。

ゲート後: **適用 266/675 = 39% / skip・保留 178 = 26% / 変更不要 231 = 34%**

## 6. リスクと安全装置

- ISBNをキーに突合するので**別版・別作品の取り違えは構造的に起きない**(ISBNが本を一意に決める)。
  実測でも「ISBN不一致」は3/90頁。順番合わせで突合すると別版併記の記事で誤爆するので**必ずISBNキー**。
- 同名別作品は**著者名ゲート**で排除(実測4/90頁)。
- Wikipedia自体の誤りは**楽天salesDateとの一致ゲート**で吸収(上記3の実測)。
- ★**同一頁で基準が混ざらないようにする**。「頁内の全巻がゲートを通った頁だけ適用」にすると
  さらに安全だが適用数は減る。どちらにするかは要判断。
- 可逆: override は行削除で元に戻る。種2は不変。

## 7. 推奨

一括で回すなら **①候補11,268件のfetch(3.4h・バックグラウンド) → ②ゲート付きoverride生成 →
③差分をTSVで人が一覧確認 → ④フルpromoteの機会(月次/週次)に合流** の順。
③を挟めば、実際に何が変わるかを適用前に全件見られる。
