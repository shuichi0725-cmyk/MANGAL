【2026-06-07 確定。 版/刷タブと購入連動の方針】

## 実装済(うる星やつらで)
- ★**版/刷タブ** = 同一(出版社×type)の複数刷(初版/新装版/復刻)を EditionSchema.versions[] で持ち、`EditionVolumes`(client)が**古い順タブ**で表示。既定選択=「**全巻ISBN有り(=完備)の最古刷**」。複数完備なら古い方。[[multi_edition_unification_pending]]
- NDL by-title で MADB未収録の新装版/復刻を網羅取得(_ndl-urusei-enum.py / _build-urusei.py)。MADB凍結の取りこぼしをNDLで補完できると実証。
- 判定は `fullStock()`(VolumeにISBN/ASINがあるか)1箇所に集約 = 将来ここを在庫APIに差し替え可能。

## ★【方針確定・2026-06-13 ユーザ裁定】在庫は追わない / 電子割引率だけこだわる
- ★ユーザ明言: **リンク先の在庫はどうでもいい(リンク先で分かる)** → **リアルタイム在庫照会・在庫タブ・3チャネルOR集約 は全部不要=破棄**。買うボタンは「買える場所へのアフィリンク」に徹する。設計が大幅に軽くなる(discovery本体に集中)。
- ★唯一こだわる polish = **電子書籍の割引率をリンクボタンの上/横にバッジ表示**(◯◯%OFF)。紙には付けない(割引概念が薄い)。
  - ★**全本を事前収穫するのは非現実的かつ無意味**(量=6.9万×巻×電子別ID + 割引はキャンペーンで数日で変わる「生もの」=焼いた瞬間腐る)。ユーザも「全部調べるのは無理」と認識。
  - ★**現実解=遅延オンデマンド**: ユーザがその漫画ページを開いた時に、**その本だけ Worker がライブ取得**(閲覧1=数API呼・短時間キャッシュ)。カタログ規模でなく**閲覧数でスケール**=現実的・鮮度OK。楽天Kobo電子書籍検索API(itemPrice→割引算出)をWorkerから。
  - ★**デフォルトは(a)リンク先任せで十分**(在庫と同じ哲学=リンク先で見える)。割引バッジは Worker導入後の任意 polish、discovery優先を圧迫しない。
  - Kindleはブラウザ強制中継ボタン([[kindle_link_browser_not_app]])+(任意)割引バッジ。
- カートリンク自体はAPI無しのISBN/ASIN deep-linkで作れる。在庫判定が消えたので**APIは割引率取得のみ**に縮小。

## ★【将来やること】版タブの提示レイアウト確定(2026-06-08 ユーザ決定)
電書ストアの「シリーズまとめカード」を参考に、版の見せ方を確定:
```
[表紙画像] [表紙画像] [表紙画像]   ← 版タブ = 表紙画像+版名 を横並び
 初版版     新装版    復刻BOX
──────────────────────────
 ここに「選択中の版の説明」(長めOK) ← ★この設計の最大価値=今まで版情報の置き場が無かった
──────────────────────────
 1巻  [試し読み][カート…]          ← 巻は【縦】に列挙
 2巻  [試し読み][カート…]
 3巻  …
```
- ★**版タブを横並び画像にできる理由** = 我々はカートが基本1つ(自分で売る/deep-link)。店は版ごとカート必須で横にすると極小化→できない。我々はその制約が無いので横スペースを表紙に使える。
- ★**巻は縦**: 将来カート(複数ストア)が増えるので1巻=1行で横スペースを確保。横並びにしない。
- ★**版の説明枠**(タブ直下)= 新設の価値スポット。今出せる情報の置き場が無いのを解決。
  - 今(データ由来): 出版社**当時名** / 刊行年 / 完結・連載 / 巻数 / 判型(新装/文庫/ワイド/復刻BOX)
  - 将来(curate+書影): 版固有解説「新装版=2006年カラー扉追加」「復刻BOX=函入り初版復刻」等
- **表紙画像スロット = 今はプレースホルダ**、書影API(Amazon/楽天)が入ったら差し込むだけ(レイアウトは画像無しでも成立)。[[openbd_eol_amazon_required]] [[store_affiliate_architecture]]
