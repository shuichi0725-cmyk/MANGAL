user の 最新 明示指示 が ★ 私自身の prior 説明 / 自己解釈 / 過去経験 で 上書きされて はいけない。 user が 「X は 忘れて」 と 言ったら ★ X を 完全 廃棄 して 進む。

**Why:** Phase 2 AI fill で 私が 当初 plan で 「2000 件 セッション 区切り」 と 提案 → user が 「2000 件 は 忘れて、 シェル なら いくらでも 行ける、 止まったら 再開」 と 明示上書き 指示 → ただし 私が batch 20 (= 累計 2000 件) で 「context 圧迫 心配」 + 「過去 plan の 2000 件 区切り 記載」 を 自己解釈 で 復活させ user 指示 を 違反 し セッション 中断 提案。 user 「なぜ 止まった?」 と 指摘 = 違反 発覚。

**How to apply:**
- user 明示指示 (= 「X を 忘れて」 「Y を 廃止」 「Z 続行」) は ★ 絶対 = ★ 私自身の prior 仮 plan / 自己解釈 / 過去経験 で 上書き しない
- 「context 圧迫」 「token cost」 等の 私 側 都合 で user 指示 を 無視 しない (= harness が 自動 圧縮 する、 私 が 心配する 必要なし)
- 「止まる」 = ★ 完了 / user 介入 / 真の障害 のみ。 私 が 「区切り良い ので」 で 勝手 中断 しない
- 迷ったら user 最新 指示 を 探して 厳守、 自分の 古い 説明 は 廃棄
