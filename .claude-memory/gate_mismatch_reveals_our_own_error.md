# 照合ゲートの不一致 = 我々側の誤りの検出器 (2026-09-07 実踏)

外部ソースと突き合わせて「著者が一致しない/巻数が合わない」時、反射的に **相手を疑って保留**にしがちだが、
**我々のデータが間違っている**ケースが混ざる。保留にすると誤りが**そのまま温存**される。
不一致は捨てずに **どちらが正しいかを一次情報(楽天live/NDL)で決める**。

## 実測 (マンバ蒸留 = [[manba_booklive_titleid_route]])

hit 300件のうち著者overlapが取れず「巻数±3」だけで通った **9件を目視**した内訳:

- **8件 = 表記ゆれ**(澤野明=サワノアキラ / 宮成樂=宮成楽 / ソラジマ=SORAJIMA /
  ÖYSTER=OYSTER / FlynnIan=イアン・フリン / SITE=SITE(Ghetto Hollywood) /
  我々が原作者だけ載せ相手が作画者だけ載せていた等)。= ゲートの偽陰性。
- ★**1件 = 我々のデータが誤り**: `neko-to-shinshi-no-tea-room`「猫と紳士のティールーム」の
  著者が **ハイソンヤギ/吉田直子** になっていた。楽天liveで全巻確認したところ
  正しくは **モリコロス**(コアミックス/ゼノンコミックス)。manba が正しかった。
- **別作品の誤採用 = 0件**。

**Why:** 照合作業の副産物として「自分の誤り」が無料で出てくるのに、
「相手が違うから保留」で捨てると二度と気付けない。保留の山は誤りの隠し場所になる。
**How to apply:** 突合ゲートを書く時は不一致を **ambiguous(保留)** と
**我々側が怪しい(要検死)** に分けて出す。目視レビューでは必ず一次情報を1回引いて
どちらが正かを決め、我々が誤りなら**別TODOとして必ず記録**してから先へ進む。
