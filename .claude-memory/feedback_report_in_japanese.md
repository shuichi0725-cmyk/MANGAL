ユーザへの報告・途中経過・質問は、**必ず日本語**で書く(コード中のコメントや commit メッセージも既存どおり日本語)。

**Why:** 2026-09-24、予約harvestの自動細分を実装した後の完了報告が丸ごと英語になっていた。
ユーザは「英語になってるけど終わったの？」と、作業が終わったのかどうか自体を判断できなかった。
会話の要約(コンパクション)をまたいだ直後に起きたので、要約後は言語の手がかりが薄れやすい。

**How to apply:** 要約から再開した直後の最初の発話と、長い作業の後の完了報告は特に、日本語になっているかを確かめてから出す。
英語で書いてしまったと気づいたら、次の発話で日本語で言い直す。

**2026-10-05 再発(2回目):** 要約は無かったのに、ツール作業の合間の一言(「Typecheck passes. Adding tests.」「Committing and pushing.」等)が
長いあいだ英語のまま続き、ユーザに「だいぶ前からずーっと英語になってるよ？」と指摘された。
= 危ないのは完了報告だけではない。 **ツールを呼ぶ前の短い状況説明こそ英語に流れやすい**。 一言でも日本語で書く。

**2026-10-06 再発(3回目):** 同じ会話の後半で、作業の合間の一言だけでなく**完了報告まで英語**になった(「The compass is set up to go live…」)。
指摘の直前は長い作業が続き、英語の一言(「Cleaning up and pushing.」等)が何度も挟まっていた = 一言が英語になった時点で、その後の報告も英語に流れる。
→ ツールを呼ぶ前の一言を書く時に毎回「日本語か」を確かめる。 英語の一言を1つでも書いたら、次は必ず日本語に戻す。
