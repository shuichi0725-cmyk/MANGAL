公式ドキュメント(https://webservice.rakuten.co.jp/documentation/books-book-search・2017-04-04版)で確認した事実:
- **page 1〜100・hits 最大30 = 1クエリ最大3,000件**。pageCount も100で頭打ち。
- `size` の値: 0全て/1単行本/2文庫/3新書/4全集・双書/5事典・辞典/6図鑑/7絵本/8カセット,CD等/9コミック/10ムックその他。
- `availability`(要求): 0全て/1在庫あり/2通常3-7日/3通常3-9日/4メーカー取り寄せ/5予約受付中/6メーカー在庫確認。
  ★7以上はAPIが受け付けない(count無し)。★**品切れの本は応答の availability が空**=どの値でも引けない。
  ★ドキュメント外の値 11 が来る(発売日3099年の仮日付品)。
- ドキュメントに載るが**実際には値が来ない**: `chirayomiUrl`・`limitedFlag`(手元の楽天キャッシュ81.8万件で非空0件)。
- Referer/Origin はドキュメントに無いが、無いと400(実測)。
- ジャンル木: `BooksGenre/Search/20121128?booksGenreId=`。001001配下= 少年12/少女24/青年58/レディース14/文庫10 の子(レーベル別)。
  ★**その他(001001012)には子が無い**。応答に itemCount は無い。

**予約harvest(`_rakuten-preorder-harvest.py`)の自動細分(2026-09-24)**:
- 発売日降順でたどるので上限で切れると**列の後ろ=当月〜近い未来**が毎回同じ所で落ちる。→ 上限にかかったクエリだけ
  子ジャンル→判型→在庫状況 の順に分けて取り直す(深さ4)。分けた先の総数合計が親に届くか毎回検算し、届かなければ次の分け方も使う。
- どの分け方にも漏れがある(実測): 子ジャンル=少年/レディースは合計一致 / 判型=その他 167,020中2,497・青年 112,768中540 が判型なし /
  在庫状況=品切れが全部漏れる(その他 167,021中 49,616 しか在庫状況を持たない)。
  → 在庫状況まで使っても届かない時は ★注意(漏れうるのは当月発売済みの品切れ本)。試験で落ちた7冊は**全部 preorders-prev に在った**
  = 発売前の日次で予約受付中として取得済み=実害なし。取り切れないクエリ/API失敗だけが ★★(進めない)。
- 試験結果: 既定設定=135回で細分なし(呼び出し増ゼロ)/ 60頁に絞る=その他が細分・欠け5(全部上記の品切れ) /
  12頁に絞る=少年・青年は子ジャンル細分で欠け0、その他は★★が正しく鳴る。実際の上限100頁ならその他のコミック判型は約65頁で収まる。
- ★**レートは `_get()` の中で守る**: 呼び出し側の sleep 任せだと0件で即breakする経路で連打→429で全停止(試験で2回実踏)。
- ★API 3回失敗は None を返し walk が `error` にする(旧実装は `{}`=「結果の終わり」扱いで黙って落ちていた)。
- 副作用: 細分すると発売日が空/年のみの本(【バーゲン本】JAN 4528…等)を拾うことがある=下流の非ISBN/発売未定ゲートで処理される。
- 同じ組み合わせ(判型→在庫状況 と 在庫状況→判型)は `_WALKED` で1回だけ取る。状態= `.cache/preorders/harvest-status.json`(split_log/unresolved/lossy)。
