2026-09-21 ユーザ指示「抜けてるデータを収集して楽天で拾えない？**ラノベと間違わないように気をつけて**」。

## なぜ要ったか(実測)

巻抜け充填の照合器は5層(G1既存ISBN / G2版元prefix / G3発売日 / G4著者 / G5 ISBN連番)を持っていたが、
**ラノベ判定が1つも無かった**。楽天収穫 5,944 item の内訳を数えたら
MFブックス63 / カドカワBOOKS33 / オーバーラップ文庫31 / アルファライト文庫30 / GCノベルズ23 /
ファンタジア文庫20 / ダッシュエックス文庫19 … が混在。
**題も著者(原作者)も同じで小説版だけ別レーベル**という型なので、題一致+著者一致では抜けない。

## 実装(定義は1箇所)

`scripts/_rakuten_match_lib.py` の **`novel_reason(series, size=None, etype=None)`**。
2つの照合器 (`_volgap-live-match.py` / `_volgap-lead-live-match.py`) が**両方これを呼ぶ**
(最初 live-match 側にローカル定義を書いたが、ドリフトするので lib へ集約した)。

- ラノベレーベル正規表現: 電撃/ファンタジア/スニーカー/オーバーラップ/ダッシュエックス/MF文庫/MFブックス/
  GA/HJ/アルファライト/アース・スターノベル/GCノベルズ/カドカワBOOKS/ノベルス/novels/青い鳥/つばさ/
  みらい/レジーナ/ベリーズ/ビーズログ/一迅社/ラノベ文庫/ビーンズ/オレンジ/コバルト/ソノラマ
- ★**救済**: レーベル名に「**コミック**」が入れば通す(ぶんか社コミック文庫=漫画。誤爆防止)
- 非漫画レーベル: 絵本/テレビ絵本/アニメ絵本/ポーズ集/資料集/写真集/図鑑
- 判型(size): 絵本/カセット・CD/図鑑/ムックその他 は拒否。**文庫・新書は頁の版が bunkobon でない限り拒否**
- ★弾いた候補は `docs/production-diagnostics/volgap-live-blocked.tsv` /
  `volgap-lead-blocked.tsv` に**理由つきで残す**(偽陽性の再検査ができるように)

## 実際に弾いた物(ゲート無しなら入っていた)

- **海の王子 → 「講談社青い鳥文庫」**(児童書の小説版)。正解は藤子・F・不二雄大全集 9784091434166
- **X-MEN → 「電撃ジュニアノベルズ」**(ノベライズ)
- 中公文庫・河出文庫・現代教養文庫版『世界の歴史』/ 時代小説文庫『丹下左膳』/ 講談社のテレビ絵本『あんみつ姫』

★`size` は MID層の収穫(volgap-live-rakuten.jsonl)には在るが、**LEAD層の収穫には無い**
(保存フィールドが違う)。LEAD側はレーベル名だけで判定している。

**Why:** 「題+著者が合う」だけでは小説版を弾けない。レーベルと判型が決め手。
**How to apply:** 楽天由来の候補を頁へ足す新しい道具を書く時は、必ず `R.novel_reason` を通す。
