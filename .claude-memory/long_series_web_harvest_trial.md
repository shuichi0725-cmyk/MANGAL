## ★流し方の罠(2026-10-29 実踏)
- `while read s; do python … ; done < list` で回すと、子が一覧ファイルを標準入力に継いで claude -p が固まる(直接実行は90秒で完走)。→ 各コマンドに `</dev/null`。
- Python が書く一覧は CRLF(`open(...,'w')`)→ bash の read で stem 末尾に \r。
- 止めた bash の流れが生き残り2本並走した。止める時は CommandLine に `_trial-long|_element-` を含むプロセスを全部 taskkill /T。
- `_lean_claude.ask` の timeout が Windows で効かず30分固まった → Popen+taskkill /T に直した(commit e412c46d19)。

## ★Haikuへの命令の型(2026-10-30 ユーザ「判断させる命令の出し方決めて」→ v0.6)
- Haikuは「選ぶだけ」: 開く頁の番号 / 採る段落の番号+役割+scope(全体/一編)/ 使わない理由(決まった選択肢)/ 同じ作品だと示す語句。 文章は書かせない(本文は道具が原文を写す)。
- 機械で確かめられることは聞かない(題・著者が頁に在るか・止め札・重複・上限)。 Haikuの答えは道具が全部検算し、通らなければ理由付きで不採用。
- 要素の判断は収集でさせない(後段 Sonnet)。 scope は後段が「一編だけ」で落とす問題への材料。
- v0.6 で直した: 同定の照合先を「同定済みの資料(Wikipedia等)」まで広げてHaikuにも見せる(v0.5は本物13頁を捨てた)/ 百科の2本目=マンガペディア / 題3字以下は著者名を足して検索 / piccoma・U-NEXTを外す。 試し3作で捨てていたマンガペディアが全部採れた。
