# 記憶とskillの棲み分け (2026-07-04 ユーザ裁定)

**Why**: やり方がskillとmemoryの両方にあると、更新が片方に入って食い違い、弱いAIはどちらを信じるか迷う。一方、戒め・実測・事故史は圧縮すると文脈が失われる。

**How to apply**:
- **戒め(feedback)・注意点・実測・事故史・データ実体** → memory。圧縮不要、巨大化は必要経費・資産。
- **手順・トリガー運用・コマンド列(やり方)** → `.claude/skills/` が唯一の正。memoryには書かない。既存memoryにやり方が居たらポインタ化して skill へ移す。
- skill化済みのやり方を将来 memory に書きそうになったら、skill 側を更新する。
- 新しい教訓が出たら: 事実は memory・そこから導く運用は skill、に分けて両方更新。

## ★索引(MEMORY.md)だけはサイズ上限がある (2026-09-06 実踏)

「記憶は圧縮不要・巨大化は資産」は **topic ファイル本体**の話。 **索引 `MEMORY.md` には読み込み上限**が在り、
24.4KB(文字)に近づくと hook が警告する。 その時にやることは:

- ★**リンクは1本も落とさない**。 詰めるのは `— ` 以降の hook 文だけ(詳細は topic ファイルに在る)。
- 詰めた後に **リンク数を機械照合**する(2026-09-06: 18.6KB → 16.8KB / 291本・消失0)。
- ★topic ファイルの中身は**絶対に要約しない**(= 上の大原則。 索引の都合を本体に持ち込まない)。

## ★CLAUDE.md も同じ (= 毎セッション自動読み込み)

CLAUDE.md に**本文**を書くと毎回読むことになる。 2026-09-06 に月次蒸留の本文を逃がした
(43,864 → 25,077字 / ▲42.8%):
- 本文 → `docs/`(例 `docs/monthly-sanity-detectors.md`) / 手順 → skill / 事実・戒め → 記憶
- CLAUDE.md に残すのは **原則・abort 条件・★索引(引く入口)** だけ
- ★逃がしたら **番人を置いて腐りを防ぐ**(`_check-sanity-registry.py` = 索引 ⇔ 本文 ⇔ 実装の3点突合)
- ★逃がす前に **移し先が同等以上を持っているか確かめ、足りない分を先に書き足す**(消してから気付かない)
