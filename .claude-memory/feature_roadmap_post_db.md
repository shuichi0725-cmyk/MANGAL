## 確定した個別方針
1. ★**種4補完(取りこぼし巻) = 楽天ブックスAPI + NDL で可能、Amazon不要**。楽天は**無料・売上ゲート無し**でISBN/正式題/巻/出版社/発売日/書影URL/在庫を返す。種4は「ISBNと発売日の確証」が要件なのでこれで完結。Amazonは将来の書影品質+中古/絶版+売上アフィリだけ。→ 監査の2d 531件(near-complete内部欠け)が着手対象。[[ndl_nonmanga_sweep]] [[store_affiliate_architecture]] [[openbd_eol_amazon_required]]
2. ★**AniList期待巻数でのlag(最新刊遅れ)専用スキャンは不要=捨て**。AniList巻数は不正確、内部欠けは別監査で見える、重大undercount(こち亀n=16型)は種4作業中に拾える。[[anilist_matching_state]]
3. ★**衝突断片の「誘導」= カノニカル+301 alias**。hana×5/shin-agatte×3が同一欠番セット=同じ巻が複数ページに分散。①NDL ISBN国コード+出版社prefixで同一性確定(c-2 merge方式) ②同一なら代表1ページ(最多巻/最古)に統合、残りはalias転送。SEO重複分散も解消。slug変更リダイレクトと兼用。[[collision_slug_investigation]]
4. ★**「今読めるか」バッジ = 電子化済みは楽天Koboで先行実装可(Amazon不要)、絶版/中古はAmazon待ち**で段階分割。
5. ★**一覧検索表(最優先候補)** = 漫画サイトは表紙グリッド一辺倒で、密度の高い**テキスト表(スプレッドシート型)**がほぼ無い=差別化。列=題/著者/出版社/年/巻数/完結状態、**列クリックでソート**、フィルター絞り込み。**API不要(既存データのみ)・爆速・低通信・スマホ一覧性最高**。既存50音ソート+フィルター資産が土台。グリッド↔表のビュー切替で共存。

## ★蔵書×コンプ×続刊 = PII完全ゼロで両立(ユーザの最大の懸念を解消)
設計原則 = **サーバはデータの中身を知らない**。Googleアカウント等不使用。
- **蔵書本体** = localStorage(端末内・ログイン無し・PIIゼロ)。未所持巻ハイライト→購入導線
- **バックアップ3段** = ①JSONエクスポート/インポート(サーバ0・自己管理) ②QR/リンク書出し(端末間移行) ③**合言葉式 暗号化同期**(ユーザの合言葉で端末側暗号化→サーバは暗号塊+乱数IDのみ保存=中身読めない=実質PII非取得。合言葉忘れ=復元不可を明示)
- **続刊通知** = ①**.icsカレンダー購読(最も無害=通知はユーザのカレンダーアプリが出す、フォローをURL埋めでステートレス)** ②新刊RSS ③PWA Web Push(購読は匿名endpointだがデバイス識別子なので嫌なら回避)
