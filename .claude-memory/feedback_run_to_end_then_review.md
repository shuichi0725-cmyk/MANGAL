全件を流す作業(ジャンル・要素の見直し 等)は、**途中で道具を直して流し済みを作り直す、をくり返さない**。最後まで流し、点検の報告は貯め、流し切ってからまとめて1回で直す。安いモデル(Sonnet)だけで進め、Opus は最後に呼ぶ。

**Why:** 2026-10-13 ユーザ原文「このままだとおなじ物を何度も修正している。完璧な物を一回で作るのではなく(多分無理)So-netだけで効率的に進めて。最後までやって、また見直す。というような方法にしないと進まないのでは?これは質問というか提案。」
直前の経緯: 1,000件流す → 点検 → 道具を直す → 1,000件を判定し直す(約4時間・$6.5・使用量の上限で中断)→ 点検 → また直して114件を判定し直す。29,000頁のうち1,000頁で2周した。

**How to apply:**
- 流す前に「後から直しが効く形」にしておく(私の解釈): モデルの生の答えを頁ごとに残し、機械の決まりの変更はモデルを呼ばずに全頁へ効かせる(`_element-review.py rebuild`・1,106頁 83秒・0円)。
- 途中で止めるのは「壊れている」時だけ(点検で問題なしが半分未満・語が全部消える類の不具合)。惜しい誤りは報告に書いて先へ。
- 他の全件もの(巻説明・エンリッチ 等)にも同じ考えを当てる = 生の出力を残す・直しは最後にまとめる。
