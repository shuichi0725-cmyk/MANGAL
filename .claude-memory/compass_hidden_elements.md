2026-10-09 ユーザ発案: 「ネタバレの要素は隠し持つことは可能か？見えないけどもってる。それによって近い物が見つけやすい的な。羅針盤でもみえないけど近い要素でマンガ自体はつながるみたいな。」
30作の結果への裁定「1よい」を受けて、合意していた順番(①線を決める → ②羅針盤に隠し要素)どおり実装した。

## 形(何がどこに在るか)
- **配るファイル = `public/data/compass-hidden.v1.json`**(約1.26MB・gzip 0.45MB)。`{"v":1,"built":日付,"k":鍵の種類数,"p":{公開slug:[番号…]}}`。
  **番号だけ・語の一覧は載せない**(データを覗いても語は読めない。番号は鍵の sha1 順で、ビルドのたびに振り直してよい)。
  既存の索引(manga-list-index / cols)は**一切変えていない** = 形式契約・名前バンプ・INDEX_FILES の結線は不要。`public/data/` は robots で Disallow 済み。
  ★形を変える時はファイル名の v を上げる(取得先は `app/compass/useHidden.ts` の HIDDEN_URL と `app/compass/page.tsx` の preload の2か所)。
- **作る道具 = `scripts/_build-compass-hidden.py`**(約12秒・モデル不使用・本番データは読むだけ)。`--dry`(統計だけ)/ `--explain <slug>`(その作品の鍵を語で見る = 手元の点検用)。
- **鍵(作品ごと)= 見えている要素(一覧索引の themes)+ 隠し要素**。①も入れるのは「Aでは見えている語」と「Bでは隠れている同じ語」を突き合わせるため。
  隠し要素の源は2つ: ① AniList のその漫画自身のタグのうち票40以上で頁に出していないもの(線に届かない語・人物/舞台系・ネタバレ印・競技名。
  成人タグ・分野・Male/Female Protagonist・Primarily *・Nudity・Sexual Content・Technical は除く)② 要素付与が書いた「隠して持つ」語 `data/seeds/element-hidden.json`
  (`_element-assign.py apply` が同時に書く / 適用済みの頁へ後から = `_element-assign.py hidden <stem> --go "…"`。ani:<英名> か和名。関連作から引き継いだ分はここに入る)。
  鍵の名前 = 訳が在れば頁と同じ日本語(訳表 → 旧辞書の順)、無ければ `en:英名`。ジャンル名と同じ語(学園 等)は鍵にしない。
- **計算 = `app/compass/compass.ts`**: `buildGraph(list, hidden?)` → `g.prox` / `proxNear(g, slug)` → `near(i, sh)`。
  近さ = 見えている共通の要素の数 sh + **0.5**(HIDDEN_W)× 隠れている共通分 × 割引。隠れている共通分 = 鍵の共通数 − sh(負は0)。
  ★割引 = 相手の鍵が **8個**(HIDDEN_FULL)を超えたら 8÷相手の鍵の数 に薄める。鍵の多い本(ONE PIECE 71・チェンソーマン 47・しゅごキャラ! 34)が
  どの本の周りにも出たため(最初は「中央の鍵の数」も基準にしたが、俺ガイル(鍵27)でまだ出たので相手の数だけで決める形にした)。
  使う所: 周りの本・広げる単位の並び/くじの重み/足切り(雑誌・年は近さ2以上、要素の枠は近さ3以上かつ見えている共通1以上)、掛け合わせ・組み替えのくじ。
  「似た要素」は、**見えている要素が5つ未満の本だけ**鍵で測る(5つ以上の本を鍵で測ると組が大きくなって重なり率が下がり、らんま1/2 が 12冊→3冊に減った)。
  ★画面に出る「共通の要素Nつ」とラベルは見えている語のまま。入口(要素の輪)にも隠し要素は出ない。
  ★隠し要素のファイルが無い/壊れている/4秒待っても来ない時は、今までと全く同じ結果(テストで固定: compass.test.ts「隠し要素」10本・全58本)。

## 実測(2026-10-09・本番の索引 69,556作)
- anilist_id のある頁 35,500 / 鍵を持つ作品 34,257 / **隠し要素のある作品 11,000**(平均 2.4個)/ 鍵の種類 540。
  鍵3個以上の作品: 見えている要素だけ 4,022 → 隠し込み 8,027(約2倍)。逆引き表の作成 +約25ms・1回の計算は変わらず(約30〜60ms)。
- 効いた例(本物の計算で前後比較 = `.cache/_compass_eval.ts`・作業用):
  SLAM DUNK(見えている要素は「更生」だけ・鍵8)= 「似た要素」出ない → 21冊(I'll・リアル・ハイキュー!!・黒子のバスケ)/ 同じ雑誌 2冊 → 50冊(先頭 I'll)。
  君に届け(見えている2・鍵7)= よく似たジャンルの先頭が こどものじかん・シガテラ → アオハライド・ひるなかの流星 /「似た要素」出ない → 50冊(ホリミヤ・ひよ恋・高校デビュー)。
  トモちゃんは女の子!(見えている1)=「似た要素」26冊(長瀞さん・宇崎ちゃん・堂島くん)。 ガンニバル = 41冊(王様ゲーム起源・屍介護・鬼畜島・うずまき)。
  俺ガイル(鍵27 = 更生・片思い・悲劇を隠して持つ)= 要素の枠に「私がモテないのはどう考えてもお前らが悪い!」が入った。
- 見えている要素が多い本(らんま・ヨナ)は顔ぶれがほぼ同じで並びが少し変わる程度 = 効くのは要素の少ない有名作。

## 未了・注意
- **本番へは未反映**(コード変更 = 「機能蒸留して」か「週次蒸留して」で出る。public/data のファイルは機能蒸留でも PUT される)。テスト環境 /compass で確認できる。
- **作り直しは手動**: 索引や訳表・要素付与が変わったら `python scripts/_build-compass-hidden.py` → commit。週次の再生成(step1)にはまだ結線していない
  (古くても壊れない = 鍵の共通数が見えている数より少ない時は足さない。ただし放置すると効きが鈍る)。ユーザがテスト環境で見てから結線する。
- 源①は「その漫画自身」の AniList タグだけ。アニメ・原作小説からの引き継ぎ(関連作あり 約6,600作)は API を1作ずつ引く必要があり未着手(トークンは使わないが数時間)。
