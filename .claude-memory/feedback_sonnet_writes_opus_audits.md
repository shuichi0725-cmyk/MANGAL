ユーザは大量作業を Sonnet 5.5 に任せ、終わったら Opus に点検させる分担を選んだ(「sonnetにやらせてみたい。問題があるようならあなたに」2026-10-01)。
②要素付与・ジャンル追加・あらすじ→キャッチ・Kobo→キャッチの4回この形で回し、点検で毎回数件〜数十件の誤りを直した。

**Why:** 書く量が多い作業はSonnetで十分速く、誤りは点検で拾える。点検する側に根拠が残っていないと検算できない。

**How to apply:**
- 指示文はOpusが書き、ユーザがSonnetのセッションに貼る。まず「試行200作で止まって報告」→Opusが点検→「残りを全部・途中で止まらない」。
- 指示文に必ず入れる: 台帳(1件ずつ slug/src/書いた文/根拠の材料/stage/model="sonnet-5.5"/日時)、純粋追加、700頁ずつ反映・最後だけpush、減少検出で止まる、本番R2はしない、最後の報告項目。
- 点検は「全件の3か所整合(manga.v2/seed/索引) → 数字・カタカナ語が材料に無いもの → 文末の途切れ → 無作為50件」。直した分は台帳に model="opus-5.5" で記録。
- 長時間ジョブの途中報告は2,000件単位でよい。定型の進捗通知には返事しない(2026-10-01 ユーザ「途中報告は細かくはいらない。2000単位とかでよいよ。返事もいらない」)。

## 2026-10-03 追記(③④ 4.3万頁で効いた型)
- **AIは「読んで選ぶ」だけ、検査と書き込みは道具**(scripts/_themes-genres-ai.py)にすると速く安全。根拠の語句が材料に完全一致しなければ書かない検査で、作り話の根拠は0件だった。
- 点検の順(効いた順): 3か所整合 → id帯ごとの付与率(後半で雑になっていないか)→ 根拠の使い回し → 無作為50 → 件数の多いキーを重点20 → 見つけた型を全件機械で洗う。
- 型の誤りは「作品が元のもの(ゲーム/映画)を題材にしている」=**原作コミカライズを題材と取り違える**型が出やすい。
- 試行は「書き込まずに止まる」にして回答ファイルを点検する方が、反映後に取り消すより安い。
