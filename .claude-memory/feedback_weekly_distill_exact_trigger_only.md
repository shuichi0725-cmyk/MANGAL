週次蒸留(本番フルビルド+R2アップ)は**「週次蒸留して」という発話のみ**で発動する。

**Why:** 2026-07-21、「本番化して」(=productionize-drafts のトリガー)を「本番公開のGO」と拡大解釈し、週次蒸留を代行起動した。ユーザの意図は「本番に載っていない全集関連頁の登録」で、サイト全体のデプロイではなかった。途中で止められ「週次蒸留は絶対『週次蒸留して』以外のトリガーで発動しないで」と厳命。

**How to apply:**
- 「本番化して」「本番に出して」「公開して」等の類語・文脈からの推論では絶対に週次蒸留を始めない。
- 週次蒸留が必要な場面だと判断したら、実行せず「本番サイトへの公開には『週次蒸留して』の発話が必要です」と案内して待つ。
- skill側にも同旨を焼き込み済(.claude/skills/weekly-distill/SKILL.md のトリガー節+NEVER)。
- 関連: [[feedback-production-deploy-gate]](テスト確認→GO→本番) — GOの解釈もこのルールが優先。

## ★2026-10-31 再発(機能蒸留で)= 3ルート全部に拡張
- 「本番に今日の反映出して」を本番デプロイの指示と取り、トリガー語なしで**機能蒸留**を起動(staging→build中にユーザ「いややめて」で停止・PUT前=本番無傷)。
- ユーザ:「週次蒸留や機能蒸留など直接トリガーが無い場合はやらないで。さっきのは週次蒸留などしたときに反映できる状態にしてという意味」。
- **How to apply(追加)**:
  - 週次蒸留して / 機能蒸留して / 差分反映して の**トリガー語そのもの**が無い限り、どの本番ルートも走らせない(`_deploy-feature.py` `_deploy-diff` 系・週次の build/r2-sync 全部)。
  - 「本番に出して」「本番に反映出して」「本番でも出して」= **次の週次等で出る状態にする**(例: テスト限定フラグ `ROUNDS = PREVIEW` → `true` にして commit/push)。やったら「次の『週次蒸留して』(コードだけなら『機能蒸留して』でも可)で本番に出ます」と報告して**止まる**。
  - skill 側にも焼込済(feature-distill / diff-deploy の NEVER 先頭)。
